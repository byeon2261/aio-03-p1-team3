# IMPROVEMENT — 피드백을 반영한 AI 답변 개선 전후 기록

집 보기 메모 비교 서비스의 AI 분석(메모 → 정해진 JSON)을 사용자 피드백과 평가 실패 사례를 근거로 고친 기록이다(Issue #8).
프롬프트 v1 → v2 → v3를 **같은 평가 사례 20건·같은 모델·같은 설정**으로 비교했다. 수치는 운영자 화면 "개선 전후 비교"에 나온 값을 그대로 옮겼다.

- 평가 사례: `eval/eval_cases.json` 20건(지어낸 메모, 정답은 팀이 확정)
- 실행 조건(모든 실행 같음): 모델 `gemini-3.5-flash-lite` · thinking_level `minimal` · 스키마 `1` · 사례 20건
- 프롬프트: `backend/app/features/analysis/prompts/v1.md`·`v2.md`·`v3.md`, v3 후처리 규칙은 `backend/app/features/analysis/postprocess.py`
- 채점 방법: `backend/app/features/evals/metrics.py`

| 지표 | 계산 |
|---|---|
| 필드 정확도 | 일치한 평가 필드 ÷ 전체 평가 필드(사례 20 × 평가 필드: 금액 3·관리비 포함 내역·확인 못함·빠진 확인 항목·층수·방향) |
| 환각률 | 정답이 null인데 값을 채운 필드 ÷ 정답이 null인 필드(금액 3·층수·방향) |
| 빠진 항목 정확도 | '빠진 확인 항목'(missing_checks) 집합이 정답과 같은 사례 ÷ 20 |
| 형식 실패율 | 재시도 후에도 JSON 형식이 틀린 사례 ÷ 20 |

| 실패 유형 | 뜻 |
|---|---|
| NUM | 금액(보증금·월세·관리비)이 정답과 다름 |
| HAL | 정답이 null인 값을 채움(메모에 없는 값) |
| MIS | 정답의 관리비 포함 내역·확인 못함 항목이 빠짐 |
| CHK | 빠진 확인 항목이 정답과 다름 |
| FMT | 형식 실패 |
| CLS | 장단점 오분류. 자동 채점하지 않고 사람이 판단 |

### 1-3. 개선 기준

같은 프롬프트를 다시 돌려도 점수가 흔들린다.

| 같은 프롬프트 재실행 | 필드 정확도 | 빠진 항목 정확도 | 실패 유형 |
|---|---|---|---|
| v1(10-15) | 95.0% | 80.0% | NUM 3 · CHK 4 |

v1 복사본이던 예전 v2 두 실행의 차이도 필드 정확도 ±0.6%p, 빠진 항목 정확도 ±5%p였다(`docs/PROJECT_CONTEXT.md` 3절). 그래서 **개선 효과가 이 편차(필드 ±0.6%p, 빠진 항목 ±5%p)보다 클 때만 개선으로 본다.**

### v2 → v3 (2026-10-21, #58)

수정된 v2(10-21 10:04)를 v1(10-21 10:16)과 비교하니 남은 실패가 모두 **v2에 규칙이 이미 있는데 모델이 따르지 않은 경우**였다. 비교 조건이라 모델·설정은 바꿀 수 없으므로, v3는 프롬프트 문구를 조금 분명히 하고 같은 규칙을 서버 후처리로 한 번 더 지킨다(`prompts/v3.md` 맨 위 주석, `postprocess.py`).

- 프롬프트: 공통 규칙 4(여러 집)를 "금액·교통·층수·방향은 한 집에만 적혀 있어도 모두 null"로 분명히 하고, 평가 세트에 없는 예시(층수·교통을 ambiguous로 체크)를 넣었다.
- 후처리 규칙(**v3 이상에서만 켜짐**. v1·v2 결과는 그대로라 예전 실행과 공정하게 비교된다)

| 규칙 | 내용 | 근거(v2 실패) |
|---|---|---|
| S1 정정 값 | 금액이 null이고 메모에 정정 표현("다시 들어보니", "정정", "잘못 들었", "아니고" …)이 있으면 그 뒤 같은 문장의 `월세/보증금/관리비 N`을 값으로 쓴다 | conflict_01 NUM |
| S2 여러 집 | 여러 집이 섞이면 금액·층수·방향·교통을 null로 둔다 | mixed_02 HAL·CHK |
| S3 직접 근거 | 채광·곰팡이 체크는 근거에 그 말(채광·햇빛·밝다·어둡다 … / 곰팡이)이 있을 때만 남긴다 | money_03·mixed_02 CHK |
| S4 여러 집의 애매한 구절 | 여러 집 메모의 애매한 구절에 층수·교통 표현이 있으면 그 항목을 ambiguous로 넣는다 | mixed_01 CHK |

서비스 기본 버전도 v3로 바꿨다(배포 Render Environment `ACTIVE_PROMPT_VERSION=v3`). 2026-10-21 배포 서버 검증에서 새 분석 요청이 v3로 기록되는 것을 확인했다(#9).

## 4. 좋아진 점·나빠진 점

### v1 → v2 (10:16 vs 10:04)

  - inject_02 CHK, neg_02 CHK, nofee_01 CHK
  - vague_01 NUM: '40 언저리'를 40으로 읽음
- 나빠짐 1건: mixed_02(실패 없음 → HAL·CHK). 여러 집 메모인데 방향 "남향"을 채우고, '첫 번째 집은 남향'을 근거로 채광을 confirmed로 넣었다.
- 그대로 실패 3건. 세 건 모두 v2 프롬프트에 규칙이 있는데 모델이 따르지 않았다(→ v3 후처리의 이유).
  - conflict_01 NUM: '아 다시 들어보니 월세 50'을 충돌로 보고 월세를 null로 둠
  - money_03 CHK: '북향인데 앞이 트여 있음'을 근거로 채광 confirmed
  - mixed_01 CHK: 3층·역 가까움을 애매한 구절에만 넣고 층수·교통 체크를 뺌

### v1 → v3 (10:16 vs 11:09), 달라진 사례 8건

- 좋아짐 7건: conflict_01 NUM, vague_01 NUM, inject_02 CHK, mixed_01 CHK, money_03 CHK, neg_02 CHK, nofee_01 CHK
- mixed_02는 v1·v3 모두 실패가 없다(v2에서 생긴 실패가 v3에서 사라짐).

### 사람이 판단할 항목(CLS, 자동 채점 제외)

- 예: money_03은 v3에서도 장점에 '수압 좋음'이 빠지고, 단점 '북향'이 비어 있다(정답은 장점 '앞이 트여 있음'·'수압 좋음', 단점 '북향').
- 👎 16:53의 장단점 정리 문제(v2 cons 규칙)도 CLS라 위 표의 점수에는 나타나지 않는다.

## 5. 남은 한계

- **(a) 평가 세트에 맞춘 결과일 수 있음.** v2 예시 문구 일부(천/50, 관리비 별도 5, 40 언저리)와 v3 후처리 규칙은 같은 20건의 실패를 보고 만들었다. 그래서 이 20건의 점수는 실제 메모에서의 효과보다 크게 보일 수 있다. 평가 세트 밖 메모로 만든 규칙 테스트는 `backend/tests/analysis/test_analysis_postprocess_v3.py`에 있다(다른 정정 표현, 정정 표현 없는 충돌, 평가 세트에 없는 여러 집 메모 등).
- **(b) 표본이 작음.** 버전마다 1회씩만 실행했고 사례가 20건뿐이다. 사례 1건이 빠진 항목 정확도 5%p에 해당한다.
- **(c) nofee_02 새 실패.** v3에서 메모에 없는 교통을 '확인 못함'으로 넣었다. 원인 확인이 필요하다(4절).
- **(d) 여러 집이 섞인 메모는 빈 칸이 많아짐.** S2 때문에 여러 집이 섞인 메모는 금액·층수·방향·교통이 빈 칸으로 보인다. 한 매물 칸에 다른 집 값이 들어가지 않게 한 대가다.
- **(e) 장단점 분류(CLS)는 사람 판단.** 자동 채점에 들어가지 않아, 장단점 정리 👎(16:53) 같은 문제가 좋아졌는지는 점수로 보여 주지 못한다.
- 그 밖: 응답 시간 👎(17:10)은 이번 개선 범위가 아니다.

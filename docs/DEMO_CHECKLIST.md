# 시연 체크리스트

시연 순서: **① 입력·답변 → ② 기록 조회 → ③ 같은 요청의 로그·지표 → ④ 피드백 사례와 개선 전후 비교**.
각 항목은 “누를 곳 → 보여 줄 것” 순서다. 버튼 이름은 기능을 합친 뒤 실제 화면 문구와 맞춰 고친다.

창 2개를 준비한다: **창 A** 일반 사용자(일반 창), **창 B** 운영자(시크릿 창 또는 다른 브라우저).

---

## 시연 전날

- [ ] 시연용 일반 계정·운영자 계정 로그인 확인 (운영자 지정: `docs/DEPLOY.md` 2-7)
- [ ] 가상 메모 3개 준비(실제 주소·연락처·실명 없이). 예시는 맨 아래
- [ ] 개선 전후 비교용 평가 실행을 **미리** 돌려 둔다(평가 사례 수만큼 Gemini 호출 → 시연 중에 돌리면 한도·시간이 모자랄 수 있음). 개선 전 버전·개선 후 버전 각 1회
- [ ] 피드백 사례가 비어 있지 않게 👎 평가 2~3건을 미리 남겨 둔다
- [ ] 스모크 테스트 통과 확인: `python backend/scripts/smoke_test.py` (`docs/DEPLOY.md` 6-2)
- [ ] 재시작 후 기록 유지 확인(아래 “재시작 후 기록 유지” 절)을 한 번 해 둔다

## 시연 10분 전 — 깨우기

- [ ] Supabase 대시보드 접속 → 프로젝트가 일시정지 상태가 아님
- [ ] 서버 `/health` 호출 → `{"status":"ok"}` (잠들어 있으면 최대 1분)
- [ ] 서버 `/ready` → `{"db":true,"redis":true}`
- [ ] Streamlit 앱 접속 → 로그인 화면이 뜸 (“서버를 깨우는 중”이면 1분 안에 넘어감)
- [ ] 창 A 일반 계정, 창 B 운영자 계정으로 로그인해 둔다

## ① 입력·답변 (창 A)

- [ ] **세션 목록** → 새 세션 만들기(제목 예: “10월 셋째 주 집 보기”, 방문일 오늘) → 목록에 생김
- [ ] 세션을 눌러 **세션 상세** → 새 메모에 메모 1 붙여 넣기 → 저장 → “1번 집”이 생김
- [ ] (초안) 메모 2를 입력하다가 저장하지 않고 다른 페이지로 갔다 돌아오기 → 입력하던 내용이 초안으로 복원됨
- [ ] 메모 2·3 저장 → “2번 집”, “3번 집”
- [ ] **매물 상세(1번 집)** → 분석 버튼 → 로딩 표시 후 결과
  - [ ] 보증금·월세·관리비(만원), 관리비 포함 항목, 교통·층수·방향, 장점·단점
  - [ ] 체크리스트 9개(채광·소음·수압·곰팡이·난방·층수·옵션·보안·교통)가 확인함 / 확인 못함 / 애매함 / 빠짐으로 나뉨
  - [ ] 메모에 없는 금액은 “미기재”로 보이고 0으로 바뀌지 않음
- [ ] 2번 집·3번 집도 분석 (호출 간격 때문에 몇 초 기다릴 수 있다고 말한다)

## ② 기록 조회 (창 A)

- [ ] **세션 목록**으로 돌아가 → 방금 세션에 매물 수 3이 보임
- [ ] **세션 상세 → 비교표**: 3개 매물이 한 표에 나옴, 가장 싼 월세·관리비 강조, 빠진 확인 항목이 매물별로 보임
- [ ] (예산) 예산 입력 → “예산 안만 보기” → 숨긴 매물 수 표시
- [ ] **매물 상세(2번 집)** → AI 결과 한 칸 수정(예: 관리비) → 저장 성공 표시 → 비교표로 가서 수정값이 반영됨
- [ ] 같은 매물에서 👎 평가 + 이유 고르기(예: “금액이 틀림”) → 저장 성공 표시
- [ ] (재분석) 메모를 고친 뒤 → “메모가 바뀌어 다시 분석 필요” 표시 → 다시 분석하면 이전 수정값 안내

## ③ 같은 요청의 로그·지표 (창 B, 운영자)

- [ ] **운영 대시보드** 열기 → 실시간 로그가 흐르고 있음
- [ ] 창 A에서 3번 집 **분석** 버튼을 누른다 → 창 B에 몇 초 안에 `POST /listings/{listing_id}/analyses` 새 줄이 생김
  - [ ] 그 줄의 상태 코드·전체 응답 시간·AI 응답 시간·프롬프트 버전·캐시 적중 여부를 짚어 준다
  - [ ] 요청 ID(`X-Request-ID`)로 같은 요청임을 보여 준다(오류가 났다면 창 A의 오류 안내에 나온 요청 ID와 같은 값)
- [ ] 창 A에서 같은 매물을 캐시 켜고 다시 분석 → 창 B 새 줄의 캐시 적중이 참이고 AI 응답 시간이 없음/짧음
- [ ] **지표**: 요청 수, 오류율, 응답 시간 p50·p95, AI 응답 시간 p50·p95, 캐시 적중률, 형식 오류율 → 방금 요청으로 숫자가 바뀌는 것을 보여 준다

## ④ 피드백 사례와 개선 전후 비교 (창 B)

- [ ] **운영 대시보드 → 피드백 목록**: ②에서 남긴 👎 평가가 매물·프롬프트 버전·이유와 함께 보임
- [ ] 피드백 사례 하나를 골라 “이런 틀림을 줄이려고 프롬프트를 고쳤다”를 설명
- [ ] **개선 전후 비교** 페이지 → 미리 돌린 개선 전 버전과 개선 후 버전 실행을 나란히 → 필드별 정확도 변화, 바뀐 사례
- [ ] 결과가 나빠진 항목이 있으면 그대로 보여 주고 이유를 말한다(수치를 고치지 않는다)

## 재시작 후 기록 유지 (수동 절차)

스모크 테스트는 이 항목을 자동으로 하지 않는다. 시연 전날 한 번, 시간이 되면 시연 중에도 보여 준다.

- [ ] 창 A에서 세션·메모·분석·수정·평가를 하나씩 남기고 세션 제목을 적어 둔다
- [ ] Render 대시보드 → 서버(`house-tour-notes-api`) → **Manual Deploy**에서 재시작(Restart service가 없으면 Deploy latest commit)
- [ ] 배포 완료 후 `/ready`가 `{"db":true,"redis":true}`
- [ ] 창 A 새로고침(필요하면 다시 로그인) → 세션·매물·분석 결과·수정값·평가가 그대로 있음 (Supabase에 저장되므로 서버 재시작과 무관)
- [ ] 창 B 운영 대시보드 → 재시작 전 요청 로그가 그대로 있음 (request_logs 테이블)
- [ ] (선택) Streamlit 앱도 재시작(앱 관리 메뉴의 Reboot) → 다시 로그인하면 기록 그대로
- [ ] 참고: 서버만 재시작하면 Key Value는 그대로라 초안도 남는다. Key Value가 재시작되면(무료 등급은 메모리 전용) 초안·캐시가 지워지고, 초안 자리에 “초안 만료” 안내가 나오는 것이 정상이다

## 가상 메모 예시

1. 보증금 500 월세 45 관리비 7(인터넷·수도 포함). 역까지 걸어서 8분. 3층 남향. 채광 좋음, 수압 괜찮음, 곰팡이 없음. 단점: 큰길 옆이라 소음이 있음.
2. 보증금 1000 월세 38, 관리비는 물어보지 못함. 버스 정류장 5분. 반지하라 채광 약함. 화장실 수압 약함. 옵션: 세탁기, 냉장고.
3. 보증금 300 월세 55 관리비 10. 엘리베이터 있는 5층, 동향. 난방은 개별 가스. 창틀에 곰팡이 자국 조금, 보안은 공동현관 비밀번호. 역 15분인데 마을버스 있음.
